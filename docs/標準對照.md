# 依據哪個標準、多嚴格

[English](standards.md)

**WCAG 2.2，A 與 AA 等級。** XamlA11y 在 WPF 的 XAML 裡找其中 8 條成功準則的違反，全部跟名稱、鍵盤、看得見的焦點、點擊大小有關
（A 與 AA 共 55 條）。它是**找問題**的工具：沒有 finding 不等於符合 WCAG、EN 301 549、Section 508 或任何法律 ——
另外 47 條沒查，這 8 條也只查到 XAML 決定得了的部分。

WCAG 是寫給網頁的。套到桌面軟體怎麼讀，看 W3C 的 [WCAG2ICT](https://www.w3.org/TR/wcag2ict-22/)（指引，不是強制要求）：
2.1.1、2.4.7、2.5.3 照原文適用，2.5.8、4.1.2 換幾個字之後適用；2.5.8 的 24 CSS 像素在 Windows 是**有效像素**，就是 WPF 自己的單位（DIP）。

## 一筆 finding 是怎麼決定的

1. **要求什麼**：成功準則的原文。
2. **WPF 實際怎麼做**：量的，不是猜的 —— UI Automation client 讀到的名稱、Tab 停在哪、焦點到的時候哪些像素變了、BoundingRectangle。
   每條規則都跟真的 WPF 視窗比過（`prototype/UiaOracle`，[量到什麼](WPF實測.md)）。
3. **Axe-Windows**（微軟 Accessibility Insights 的引擎）當第二意見。它的名稱規則引用 Section 508 502.3.1，其餘引用 WCAG 4.1.2 與 2.1.1。

`fail` 的意思是：XAML 自己就決定了，準則也沒有留餘地。`warn`、`info` 的意思是：可能沒問題，原因 XAML 看不出來。

| 種類 | WCAG 2.2 | 預設 | 為什麼是這一條 | 什麼情況不算違反 |
|---|---|---|---|---|
| `missing-name` | 4.1.2 (A), 1.1.1 (A) | fail | 4.1.2：名稱要能由程式判定。內容是圖示時還有 1.1.1：控制項要有說明用途的名稱。 | 名稱在程式碼裡設，工具看不到（看得到那段程式碼時會說「不知道」）。 |
| `text-not-in-name` | 4.1.2 (A), 2.5.3 (A) | fail | 2.5.3：名稱要包含畫面上看得到的文字。名稱是空的，或（頁籤、清單項目、超連結）是型別名、一個空白。 | 同上。 |
| `meaningless-name` | 4.1.2 (A), 1.1.1 (A) | fail | 私用區字元、空白、型別名、路徑資料說明不了用途。 | — |
| `input-no-name` | 4.1.2 (A), 1.3.1 (A) | fail | 1.3.1：欄位旁邊的標籤是一種關係，程式也要讀得到。 | 名稱在程式碼裡設。 |
| `list-no-name` | 4.1.2 (A), 1.3.1 (A) | warn | 清單也是使用者介面元件；Axe-Windows 依 Section 508 502.3.1 報它。 | 只有一個、用途明顯的清單沒名稱，有的稽核員接受。 |
| `widget-no-name` | 4.1.2 (A) | warn | 也是使用者介面元件，Axe-Windows 會報。`Menu`、`ToolBar` 是 info。 | 旁邊的文字已經說完的進度條。 |
| `item-type-name` | 4.1.2 (A) | warn | 名稱讀得到，但是類別名，認不出是哪一項。 | 類別的 `ToString()` 來自這支看不到的地方（函式庫的基底類別）。 |
| `silent-tab-stop` | 4.1.2 (A) | warn | 拿得到焦點的東西，名稱與角色都讀不到。 | 程式碼把焦點轉出去了，或這個元素不會出現在 Tab 走得到的地方。 |
| `name-differs` | 2.5.3 (A) | warn | 名稱要包含畫面上看得到的文字。兩邊都寫死的才比；大小寫、標點、符號不算（照 WCAG 的說明）。 | 那段字不是標籤：操作說明、例子、數值。 |
| `symbol-name` | 1.1.1 (A) | info | `×` 或表情符號可能說明得了用途，也可能不行。 | 符號的名字剛好就是它做的事。 |
| `same-name` | 2.4.6 (AA) | info | 標籤要說明用途。WCAG 沒有要求標籤不能重複；Axe-Windows 會報同名的兄弟（它放在 4.1.2）。 | 前後文分得出來：會念出來的群組、標籤。 |
| `mouse-only` | 2.1.1 (A) | fail | 所有功能都要能用鍵盤操作。 | 別的地方做得到同一件事，或輸入取決於指標走的路徑。 |
| `not-in-tab-order` | 2.1.1 (A) | warn | 移出 Tab 順序，就只剩別的路到得了。 | 有別的路：快速鍵、選單、方向鍵。 |
| `focus-not-visible` | 2.4.7 (AA) | fail | 鍵盤焦點指示要看得見。 | 焦點由程式碼或沒量過的佈景畫（「不知道」，或 `themeShowsFocus`）。 |
| `small-target` | 2.5.8 (AA) | warn | 小於 24 × 24，又用不了間距例外。 | 等效、行內、使用者代理、必要這幾個例外。 |

常見、但這支**不**這樣說的兩件事：

- **3.3.2 標籤或說明**要求的是人看得到的標籤。看得到標籤、沒有無障礙名稱的欄位符合 3.3.2，違反的是 1.3.1 與 4.1.2。
- **2.4.3 焦點順序**管的是順序。根本不在順序裡的控制項是 2.1.1。

## ToolTip 不是名稱，但可能聽得到

WPF 把 ToolTip 放進 UI Automation 的 HelpText。NVDA 會把 HelpText 當成描述（2026-11-24 用 NVDA 2026.2 實跑過，見 [NVDA 怎麼念](WPF實測.md#5d-nvda-怎麼念)），念在型別後面（「按鈕 刪除」），所以有些使用者真的聽得到。
4.1.2 要的是**名稱**，Axe-Windows 也報同一個控制項，所以還是 `fail`。

## 其他標準

| | 用哪一版 | 差在哪 |
|---|---|---|
| **EN 301 549**（歐盟；第 11 章是軟體） | V3.2.1（2021）用 WCAG 2.1 A 與 AA。V4.1.1 在 2026 年 9 月發布，改用 WCAG 2.2；刊登公報之前仍以 V3.2.1 為準（[AccessibleEU](https://accessible-eu-centre.ec.europa.eu/content-corner/news/european-accessibility-standard-en-301-549-has-been-updated-2026-09-07_en)，2026-09-07）。2026-11-23 [執委會的清單](https://digital-strategy.ec.europa.eu/en/policies/web-accessibility-directive-standards-and-harmonisation)上最新的仍是 V3.2.1；Deque 預期 2027-01-22 刊登。 | `--standard en301549`（V3.2.1 不要求 2.5.8）或 `--standard en301549-v4`。 |
| **Section 508**（美國） | 軟體用 [WCAG 2.0 A 與 AA](https://www.access-board.gov/ict/)（E207.2），另加 502.3.1：角色、狀態、名稱、描述要能由程式判定。 | `--standard section508`：WCAG 2.0 沒有 2.5.3 與 2.5.8。 |
| **網站無障礙規範**（台灣） | 115 年修正版對齊 WCAG 2.2，115 年 11 月 30 日生效。 | 適用範圍是公眾**網站**，沒有提到桌面軟體。檢測碼是給網頁用的，所以這支不標；`--lang zh-Hant` 的準則名稱用它的。 |

### 選一個標準

`--standard wcag22`（預設）、`wcag21`、`wcag20`、`en301549`、`en301549-v4`、`section508` 與 `--level A|AA` 決定哪些種類算在內、
報告上寫哪一條。WPF 怎麼處理你的 XAML 不會變。準則全不在那個標準裡的種類就不報，除非設定檔的 `rules` 明寫。

條號是 2026-11-24 照標準原文查的（EN 301 549 第 11 章，V3.2.1 取「非封閉功能」那一層；Section 508 的 ICT 標準）。
不管選哪一個，JSON 與 SARIF 都帶全部；HTML 寫所選標準的（選 WCAG 時寫全部），Markdown 只寫所選標準的：

| WCAG | EN 301 549 V3.2.1 | EN 301 549 V4.1.1 | Section 508 |
|---|---|---|---|
| 1.1.1 | 11.1.1.1.1 | 11.1.1.1 | E207.2 |
| 1.3.1 | 11.1.3.1.1 | 11.1.3.1 | E207.2 |
| 2.1.1 | 11.2.1.1.1 | 11.2.1.1 | E207.2 |
| 2.4.6 | 11.2.4.6 | 11.2.4.6 | E207.2 |
| 2.4.7 | 11.2.4.7 | 11.2.4.7 | E207.2 |
| 2.5.3 | 11.2.5.3.1 | 11.2.5.3 | – |
| 2.5.8 | – | 11.2.5.8 | – |
| 4.1.2 | 11.4.1.2.1 | 11.4.1.2 | E207.2 |
| 名稱是空的 | 11.5.2.5 | 11.5.2.5 | 502.3.1 |

`E207.2` 是整套 WCAG 2.0 的 A 與 AA，508 沒有替軟體逐條編號。最後一列是「物件資訊」：名稱要能由程式判定。
它跟 `missing-name`、`text-not-in-name`、`input-no-name`、`list-no-name`、`widget-no-name`（名稱是空的時候）一起標；有名稱、只是念不出意思的不標。

產品要不要符合哪一個，是看產品與販售地區的法律問題，這一頁不回答。

## 沒查的，要靠誰

同一家的其他工具補一部分：[XamlContrast](https://github.com/HSU-YU-MING/cornhsu-xamlcontrast) 查 1.4.3 與 1.4.11，
[XamlFit](https://github.com/HSU-YU-MING/cornhsu-xamlfit) 查換了語言之後被切掉的字。其他要人來看，桌面軟體最常出問題的是這些（HTML、Markdown、JSON 報告會列出所選標準裡有的）：

| WCAG 2.2 | 怎麼檢查 |
|---|---|
| 1.3.2 有意義的序列 (A) | 用螢幕閱讀器念一遍視窗，順序通不通。 |
| 1.4.1 色彩使用 (A) | 有沒有東西（錯誤、狀態）只靠顏色表示。 |
| 1.4.3 對比（最小）(AA) | 文字跟背景 4.5:1（大字 3:1）。XamlContrast 會查。 |
| 1.4.4 調整文字尺寸 (AA) | WPF 不跟 Windows 的文字大小走，App 自己有沒有放大到 200% 的辦法。 |
| 1.4.11 非文字對比 (AA) | 框線、圖示、焦點框跟背景 3:1。 |
| 1.4.13 懸浮或焦點內容 (AA) | ToolTip、彈出視窗能不能關掉、滑鼠移得上去、不會自己消失。 |
| 2.1.1 鍵盤 (A) | 把滑鼠收起來，每件事做一遍。程式碼裡掛的事件這支看不到。 |
| 2.1.2 無鍵盤操作陷阱 (A) | 每個控制項（編輯器、表格也是）用 Tab 或 Esc 出不出得來。 |
| 2.1.4 快捷鍵 (A) | 單一字母的快速鍵關不關得掉。 |
| 2.4.3 焦點順序 (A) | Tab 走的順序合不合理；對話框關掉之後焦點在哪。 |
| 2.4.6 標題和標籤 (AA) | 名稱說不說得清楚做什麼。這支只看有沒有名稱、並排的是不是一樣。 |
| 2.4.11 焦點不遮蔽（最小）(AA) | 固定的工具列、彈出視窗會不會蓋住有焦點的控制項。 |
| 2.5.7 拖曳動作 (AA) | 不拖曳做不做得到。 |
| 3.2.1 焦點、3.2.2 輸入 (A) | 拿到焦點或改值的時候會不會冒出意外的事。 |
| 3.3.1 識別錯誤 (A)、3.3.3 錯誤建議 (AA) | 錯誤有沒有用文字說、連到那個欄位。 |
| 3.3.7 冗餘輸入 (A)、3.3.8 無障礙認證（最小）(AA) | 同一個資料要不要輸入兩次；登入要不要解謎。 |
| 4.1.2 名稱、角色和值 (A) 其餘部分 | 自訂控制項的角色、狀態、值：`OnCreateAutomationPeer`。 |
| 4.1.3 狀態訊息 (AA) | 「已儲存」有沒有念出來：`AutomationProperties.LiveSetting` 與 `RaiseAutomationEvent`。 |

準則名稱照台灣「網站無障礙規範」115 年修正版。等級與編號跟 [W3C 的資料](https://www.w3.org/WAI/WCAG22/wcag.json) 核對（`tests/XamlA11y.Tests/wcag22.json`）。
